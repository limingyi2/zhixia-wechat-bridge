# 虚拟机部署 · 三个脚本的分工

三个 `.cmd` 是一套，别混用。**记住：真正要双击的只有一个。**

| 文件 | 什么时候跑 | 说明 |
|---|---|---|
| `GO.cmd` | **第一次**，且你是用微信传文件进来的 | 解压 `zhixia_pkg.zip`、装运行库、建桌面快捷方式 |
| `zx.cmd` | **之后每次** | 装包检查 → 开隧道 → 起桥接。**桌面图标指向它** |
| `FIX_AND_RUN.cmd` | `zx.cmd` 报 `PKGS COPY FAILED` 之类装不上时 | 先把 `C:\zx` 整个清干净再装一遍 |

---

## 为什么不直接双击 `.bat`

这个项目的 `.bat` 扩展名关联曾经是坏的，shell 会弹「选择打开方式」——
那台机器的 `HKCR\batfile\shell\open\command` 等于 `"%1" %*`，
即**把 .bat 当 exe 直接执行**而不是交给 `cmd.exe /c`。

✅ 根治是**改用 `.lnk`**：shell 直接执行目标，**根本不做扩展名查询**。
所以桌面上那个图标是 `启动麦麦桥接.lnk`，指向 `zx.cmd` 的等价调用。

## `zx.cmd` 的三个阶段

```
[1/3] installing packages, about 2 minutes ...
[2/3] tunnel to the cloud brain ...
[3/3] starting the bridge ...
```

第一次跑要拷运行库（34MB，1~2 分钟），之后跳过安装直接起，几秒钟。

### payload 从哪找

`zx.cmd` 按这个顺序找，**第一个命中的就用**：

1. **脚本自己所在的目录** ← `GO.cmd` 解压后就地展开，最常见
2. `D:\` / `E:\` / `F:\` 根目录 ← 挂载 ISO 的光驱，
   **硬件级，不依赖 Guest Additions**（而 Guest Additions 经常掉）
3. `\\vboxsrv\zhixia\_setup\` ← 共享文件夹活着的时候

顺序不能改：早期版本只查光驱和共享，导致「解压成功了却找不到 payload」。

### 日志写 `C:\zx\logs\zx.log`，**不写共享目录**

共享目录可能在跑到一半时断，**日志写进去就正好丢掉了最需要的那部分证据**。

## 常见报错

| 报错 | 原因 | 怎么办 |
|---|---|---|
| `NO SSH CLIENT` | Win11 默认没装 OpenSSH 客户端 | 设置 → 应用 → 可选功能 → 添加「OpenSSH 客户端」 |
| `PKGS COPY FAILED` | Guest Additions 没生效 | 试 `Win+R` 输 `\\vboxsrv\zhixia`，能打开说明共享正常；或改用 ISO 挂载那条路 |
| `cannot find the payload folder "pkgs"` | 三个地方都没找到 | 看窗口里打印的「我找过哪里」那段 |
| `TUNNEL FAILED` | 云机器没开机 / sshd 没起 | 查大脑侧 |
| `NO PYTHON FOUND` | 虚拟机里没 Python | 装 3.12（**`.pyd` 全是 cp312**）|
| 装好了但群里不说话 | `chat_name` 还是空的 | 看 `docs/部署手册.md` 第 3 步 |
