# 微信接入 · 路线对比（2026-10-04）

> 起因：B站教程 BV1D5Gi6QENr《让你的小ai接入个人微信号（基于 astrbot 的 wechat bot）》
> 下面是把那条教程顺着挖到底之后的结论。**结论跟教程给的方案不一样**。

## 一句话结论

教程推荐的三个项目都不该整包用；**真正有价值的是它们共同的底层库 `wxauto`，而它已经出了支持微信 4.x 的 4.0 版**。
直接写一个 `wxauto4` 桥接脚本接知夏大脑，比教程的三层架构（WeFlow + bridge + AstrBot）简单得多，且免费。

---

## 一、教程里的三个项目，分别是什么

### 1. `alingalingling/Astrbot-wechat-bot` —— **视频这一版**（旧）

代码在 `master` 分支的 `wechat-bot-bridge-public/`。

- 原理：**wxauto 监听微信 + 调 AstrBot Open API**（`localhost:6185/api/v1/chat`）
- 🔴 **只支持微信 3.9.x**。README 原文：*"微信 3.9.x 已被服务器端封禁，登录时会提示'版本过低'"*，
  要靠 `wechat_patcher.py`（pymem 内存补丁）绕过，**每次重启微信都要重打一次**
- 🔴 README 特性里明写：**"微信群聊仅 @回复，不主动发言"**
- 抢焦点：README 自己承认 *"由于 wxauto 库使用，必然会产生和你抢鼠标键盘/抢焦点情况"*
- 依赖 Ollama 做 embedding

**→ 这条路现在基本走不通**：微信 3.9 被服务端封了，登录得靠内存补丁苟着，而且它明确不做主动发言。

### 2. `alingalingling/Akasha-WeChat` —— **新版**（仓库子目录 `wechat-weflow-bridge-ob11/`）

- 原理：**WeFlow 收（SSE 推送）+ UIA 键盘模拟发**，包成 **OneBot v11** 协议接 AstrBot
  ```
  微信 ←→ WeFlow ──SSE──→ bridge ──WebSocket 客户端──→ AstrBot(aiocqhttp 服务端)
  ```
- 有完整文档、配置示例、Web 控制面板（8766）
- `group_reply_mode`: `"mention"`（仅 @ 回复）/ `"all"`（全回）
- ⚠️ 但**多两层不确定**：
  - 要装 **WeFlow**，而 WeFlow 自己的 README 写着「**需要配套的第三方可插拔组件（本项目依赖自定义的原生解密组件，需自行设计）**」—— 能不能跑通取决于这个解密组件
  - 还要装一整套 **AstrBot**
- 它的 bridge 是 **OneBot v11 客户端** —— 意味着我们可以**自己写一个 OneBot v11 服务端**替掉 AstrBot，
  直接接知夏大脑。（这条以后如果真要用 OneBot 生态，是个好入口。）

### 3. `Kilincocomilk/WeeMessenger` —— 只是个**发送器**

- WebSocket / HTTP 收指令 → UIA 操作微信把消息发出去
- **不收消息**。所以它必须配上面某一个用
- 有"鼠标漫游"轻度防检测；要求微信 **4.1.9+**

### 共同底层

三个项目**都建立在同一个东西上：`wxauto`（Windows UI Automation 本地桌面自动化库）**。
分工只是：谁负责收、谁负责发、谁负责当大脑。

## 二、真正的发现：`wxauto4`（支持微信 4.x）

官方文档 `docs.wxauto.org/docs/install.html` 写明：

| 项 | 值 |
|---|---|
| 环境 | Python 3.9–3.13，**OS：Windows 10/11 + Windows Server 2016/2019/2022** |
| 微信 | **4.1** |
| 免费版 | `pip install wxauto4`（PyPI `41.1.7`，wheel `win_amd64`，2.7MB）仅 py3.9–3.12 |
| 免费版版本兼容 | **最新支持到客户端 203.0.113.10** |
| Plus 版 | `pip install wxautox4`（`41.2.1`，5.5MB），需激活码 |

关键 API：

```python
from wxauto4 import WeChat          # 免费版
wx = WeChat()
wx.SendMsg("晚安", who="四人群名")   # 发群
wx.SendMsg("开会了", who="群名", at=["张三"])  # @群成员
wx.ChatWith("群名"); msgs = wx.GetAllMessage()  # 轮询读消息
```

### 免费版 vs Plus 版（4.0），这才是取舍点

| 能力 | 免费 `wxauto4` | Plus `wxautox4` |
|---|---|---|
| 发消息（私聊/群/@） | ✅ | ✅ |
| 读消息 | ✅ 但只能**轮询** `ChatWith`+`GetAllMessage` | ✅ |
| **后台监听** `AddListenChat` | ❌ **Plus 专属** | ✅ 聊天独立为**子窗口**，不干扰主窗口 |
| 群成员/群管理 | ❌ | ✅ |
| 自动登录 | ❌ | ✅ |
| 下载群文件 | ❌ | ✅ |
| 成本 | 0 | 激活码，1 年订阅，**绑一台电脑不可解绑** |

🔴 **免费版的真代价**：没有后台监听 → 只能轮询，而轮询要 `ChatWith(群)` 切窗口，
**会来回切换你微信当前的聊天窗口**（第三方项目 `XXXDai/wx-plan-monitor-client` 实测印证，称"属正常现象"）。
> 在**云端**跑无所谓（那个桌面没人用）；在**你自己电脑上**跑会很难受。

价格：激活码要注册 `Du'sAPI` 后登录 `wxauto.org/purchase` 购买（文档未公开标价）。

### 风险声明（官方自己的话）

- wxauto 是第三方工具，**非腾讯官方**；"使用第三方自动化可能受到软件版本、账号状态、平台规则及风控影响"
- **低权重账号**（新注册 / 长期不活跃 / 未实名 / 未绑卡）更危险
- 官方**不提供**协议破解、DLL 注入、内存修改、认证或验证码绕过

## 三、云端能不能跑？——**塞不下**（实测）

2026-10-04 实测 `<云机IP>`：

| 指标 | 值 |
|---|---|
| 内存总量 | 1966 MB |
| **可用** | **374 MB**（负载 80%） |
| 6379 Redis / 8059 协议 / 8788 大脑 | 都在监听 |

微信 4.x PC 客户端是 Chromium 内核，客户端本体 + 自动化开销至少 **300~600MB** → **374MB 塞不进去**。

另外两个坑（社区实测）：
1. **RDP 断开会锁屏 → UIA 失效**。必须换 VNC（RealVNC / 向日葵）或 `tscon /dest:console` 保持会话
2. **异地登录风控**：*"云服务器最好买你所在城市或临近城市的，因为有几率触发微信异地登录风控"* ——
   杭州这台对烟台用户就是异地（这正是 859 卡住的那一关）

## 四、已排除的方案（别再回头）

| 方案 | 为什么排除 |
|---|---|
| 微信官方 **ClawBot**（openclaw-weixin / iLink） | 官方 FAQ 明写：**无法加入任何微信群聊**、**不能主动发消息**、不识别群成员身份 —— 你要的三条一条都给不了 |
| **Gewechat**（AstrBot 文档推荐的个人微信适配器） | 本质也是 iPad 协议，会撞上同一个异地验证；且是 Docker（Linux），我们是 Windows Server |
| **WeChatFerry / wxhelper**（Hook 注入） | 锁死微信小版本、特征明显、封号风险最高、微信一更新就失效 |
| **859 iPad 协议**（已部署在云上） | 卡在异地验证（杭州 IP），扫码后只给"取消登录"，过不去 |
| **简幻_fun SFE4.0**（16核16G 那台） | 不是云服务器，是**游戏托管平台**（Docker 容器 + start.sh），无 root SSH、无 Windows |

> 859 那套**先留着别删**（Redis/协议/bot 三个进程共约 35MB，端口都在）。万一要用还能回去。
