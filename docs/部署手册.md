# 麦麦微信桥接 · 部署手册

> 这份文档的用途：**以后把桥接部署到虚拟机时照着做**，不用重新摸索。
> 每一步都写了「怎么确认这一步成功了」，不只是写「做这个动作」——
> 部署最容易卡住的地方不是做错，而是做完不知道有没有成。

---

## 0. 这套东西是干什么的

让知夏（人格 `preset_group`）在微信群里以真人方式接话。

```
虚拟机 / 云服务器                云端大脑
┌──────────────────┐            ┌────────────────┐
│ 微信（麦麦小号）   │            │  人设 / 记忆    │
│      ↕ UI 自动化  │  SSH 隧道   │  gate 闸门      │
│ wxauto_bridge.py │ ─────────> │  DeepSeek       │
│      ↑           │  18787     │                 │
│ zx_launcher.py   │            └────────────────┘
│ （唤醒闸门+守护）  │
└──────────────────┘
```

🔴 **安全闸在代码层，不靠自觉**：桥接启动时核对 `wxid` 必须是
`<小号wxid>`（麦麦），且 `<大号wxid>`（大号）在黑名单里。
对不上直接拒绝运行，**一条消息都不会发**。两道闸是独立的。

## 2. 前置条件

| 条件 | 要求 | 怎么确认 |
|---|---|---|
| 微信版本 | 4.1.15 已验证可用（4.1.8 也测过）| 微信 → 设置 → 关于 |
| 登录的号 | **只能是麦麦小号**。大号绝不能在同一台机器上登录 | 启动器第 4 步会打印 `id`，核对 |
| Python | 3.12（`pkgs` 里的 `.pyd` 全是 **cp312**）| `python --version` |
| 网络 | 能连云端大脑 8788（走隧道时不需要公网）| 启动器第 1 步 |
| 内存 | 2G 勉强够，微信本身吃内存 | — |

🔴 **虚拟机内存给到 2G 以上**。微信 + Python + wxauto4 同时在跑，
内存不够会导致控件树建不出来，表现和「版本不兼容」一模一样。

## 3. 部署步骤（虚拟机）

### 第 1 步：把文件送进虚拟机

**方式 A：共享文件夹（推荐）**

宿主机共享目录命名为 `zhixia`，虚拟机内可见 `\\vboxsrv\zhixia`。
`zx.cmd` 会自动在三个地方找 payload，顺序是：
1. 脚本自己所在的目录（`GO.cmd` 解压后就地展开，**这是最常见的情况**）
2. `D:\` / `E:\` / `F:\` 根目录（挂载 ISO 的光驱，不依赖 Guest Additions）
3. `\\vboxsrv\zhixia\_setup\`

所以只要 `pkgs` 目录在这三个地方之一就能跑。

**方式 B：微信传文件**

把 `GO.cmd` 和 `zhixia_pkg.zip` 一起发到虚拟机（建议发到**同一个文件夹**，
不同文件夹也能跑，`GO.cmd` 会自己找 zip 并打印它找过哪里）。
在虚拟机里双击 `GO.cmd` → 它解压出 `pkgs` 等文件并建好桌面快捷方式。

> ⚠️ **`GO.cmd` 和 zip 必须在同一个目录**。分开放它也能找，但会多一步搜索，
> 且 zip 大（17MB）时微信传输可能截断，传完先核对大小。

### 第 2 步：双击桌面上的启动图标

桌面上会有 `启动麦麦桥接`。**双击它，不要双击 `.bat`**。

```
[1/5] tunnel to the cloud brain        ← 隧道
[2/5] WeChat                           ← 微信在跑吗
[3/5] WeChat accessibility tree        ← 唤醒无障碍闸门
[4/5] attaching to WeChat through wxauto4   ← attach + 核对 wxid
[5/5] groups                           ← 列出真实群名
```

看到这五行都过了，就接上了。

### 第 3 步：第一次要填群名

第 5 步会**列出微信里真实的会话名**，照抄一个（**一字不差**）填进
`C:\zx\wxbridge.local.json` 的 `chat_name`。

🔴 **别凭记忆手打群名**。之前就出过一次：用户口述「PRIVATE_CHAT_REMOVED」，
而截图上是「相儒相饽一家人」——差一个字，桥接会一直盯着别的窗口，
看起来完全像「她不理人」。

### 第 4 步：填 token

从大脑那台机器的 `C:\Vigil\config\config.json` 里读 `brain_token`，
填进 `C:\zx\wxbridge.local.json` 的 `brain_token`。

🔴 **这个值等同于凭据**：填错就是 HTTP 401，桥接打印「连不上大脑」然后退出。
**仓库是 PUBLIC，真值永远不进仓库**，`config-example/` 里那份是空的。

### 第 5 步：再双击一次启动

改完配置必须**重新启动**才生效。日志出现这一行就是成了：

```
[大脑] 用 http://127.0.0.1:18787
[运行] 每 5.0 秒看一次群「XXX」，每 3 轮复查一次身份
```

### 第 6 步：测

在群里发一条消息。日志里应该出现：

```
[收到] 某人：消息内容
[发送] OK '她的回复'
```

**验收看 `发送 OK` 和回复内容，不要看语气。** 语气像不像人跟链路通没通
是两件独立的事。

## 4. 日志在哪（出问题先看这里）

| 文件 | 位置 | 记什么 |
|---|---|---|
| `launcher.log` | 机器上 `C:\zx\` | 启动器走到第几步、桥接退出码 |
| `bridge.log` | 机器上 `C:\zx\` | **桥接自己打印的一切**（为什么拒绝运行都在这）|
| `wxauto_logs\app_*.log` | 机器上 `C:\zx\` | wxauto4 库自己的日志 |
| `zx.log` | 虚拟机 `C:\zx\logs\` | `zx.cmd` 的安装/启动过程 |

🔴 **`bridge.log` 是查桥接问题的第一站**。之前桥接静默退出，
`launcher.log` 只记一句「exited with code 1」不指名任何原因——
就是因为子进程输出没落盘。现在启动器把子进程输出同时 tee 到控制台和
`bridge.log`，缺什么一目了然。

## 5. 症状 → 原因对照表

| 症状 | 真实原因 | 怎么确认 |
|---|---|---|
| 群里没反应，日志无 `[收到]` | 桥接没起来 / 盯着别的窗口 | 看 `launcher.log` 有没有到第 5 步 |
| `[X] connect failed: 401` | `brain_token` 是空或不对 | 比对两边 `brain_token`（12 位） |
| `[X] 未找到已登录的客户端主窗口` | 无障碍闸门没唤醒 | 看 `[3/5]` 的 `action:` 那行 |
| `[跳过] 某人：xxx` | 本机快筛拦掉了 | `mention` 模式下没 @ 就会被扔，**改 `gate`** |
| 一直不主动说话 | 撞上静音时段（23:00–07:00）| 被 @ 仍会回 |
| 抢微信前台 | `listen: false` 的固有代价 | `pause_when_away: true` 会在你用别的软件时让路 |
| `ModuleNotFoundError: win32gui` | pywin32 的 `.pyd` 在子目录 | 四个子目录都要在 `sys.path`，见 `zx_launcher.py` 顶部注释 |

## 6. 已知的技术约束（别重复踩）

### 🔴 微信 4.x 的无障碍闸门
微信 4.x 是自绘 UI，**Qt 只在检测到无障碍客户端时才构建完整控件树**。
闸门关着时 `WM_GETOBJECT` 只返回 Qt 空壳，wxauto4 找不到 `mmui::MainWindow`。
`zx_uia_wake.py` 靠置 `SPI_SETSCREENREADER` + 写闸门字节激活它，
**并校验 `mmui::` 控件是否真的出现，没出现就回滚**。

闸门 RVA 随微信版本漂移（社区实测 `0x0AE2B0C8` 对应 203.0.113.10，我们是 203.0.113.10），
但代码内置 DLL 反汇编扫描，**版本升级不用改代码**。

### 🔴 微信 4.x 只给「当前显示出来的那部分」注册 UIA 控件
这是 `wxauto4/param.py` 明文写着的**设计**，不是坏了。
`CHAT_WINDOW_SIZE = (1200, 4800)` 就是为了拉大窗口提高容错。
所以微信窗口太小 → 控件树建不全 → 表现为 attach 失败。

### 🔴 子窗口模式（`listen: true`）实测不可靠
同一段代码两次跑，一次读到 2 条、一次读到 0 条；
`AddListenChat` 的回调从头到尾没触发过。**保持 `false`。**

### 🔴 云端配置有两份，只有一份活着
`paths.py` 按自身所在目录算，运行时读 `C:\Vigil\config\`。
`C:\Vigil\brain\config\` 是**废弃副本** —— 查它会得出「配置根本没生效」
这种错误结论。

### 🔴 大脑 8788 端口是写死的
在 `server.py` 里，改 `config.json` 的 port 无效。

## 7. 换回云端 / 换到虚拟机

现在跑在腾讯云的一台 Windows Server 上（地址见本地那份 `wxbridge.local.json`，
不写进仓库）。**虚拟机方案完整保留**，
云服务器到期随时可切。切换只改两处：

1. `wxbridge.local.json` 的 `brain_urls` 第一个地址（隧道端口不变）
2. 运行 `zx.cmd` 而不是 `zx_launcher.py`（`zx.cmd` 多了装包和拉隧道）

其余（桥接本体、闸门、云端大脑、人设）**两边完全共用，不用改**。
